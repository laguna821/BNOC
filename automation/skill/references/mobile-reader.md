# 모바일 읽기 규약

표 제목(caption)도 각 표의 실제 너비로 읽혀야 한다. 모바일에서 table을 block으로 바꿀 때 caption을 table-caption으로 남기면 브라우저가 폭을 한 글자로 계산할 수 있다. 320/390px·22px에서 caption의 폭과 첫/마지막 글자, 행 제목과 셀 내용을 함께 확인한다.

해석과 충분한 서술이 우선이라는 원칙은 모바일 가독성이나 읽기 도구를 생략해도 된다는 뜻이 아니다. 2026-10-18 최신본의 세로형 원어 표와 고정 하단 도구를 기능 기준으로 삼는다. 목차·문단·그림 수는 본문에 맞게 달라질 수 있다.

정론·정행·현대 적용의 세 축은 모든 글의 공통 길찾기이며 각 해설에서도 이름을 분명히 표시한다. 주제별 목차를 보존하더라도 이 세 축을 합치거나 은유 제목만으로 감추지 않는다. reading-axes.json은 실제 해설 위치와 개인·공동체·공적 적용의 문장을 연결해야 한다. 공통 목차를 눌렀을 때 접힌 해설을 열고 요약 상태에서 전문으로 돌아와 해당 설명을 읽을 수 있는지 확인한다.

서체 이름이 같다는 것만으로 스타일 일치를 판정하지 않는다. 최신본과 같은 폭·본문 크기·테마에서 표시 제목/절 제목/해설 제목/내부 소제목/본문/원어·표/캡션/읽기 도구의 계산된 크기·굵기·색상·행간을 대조한다. 최신 누가10의 editorial_roles.css를 공통 역할 기준으로 사용하며, 기존 서체 내장본에는 같은 WOFF2를 중복 추가하지 않는다. 고유 CSS 변수와 저장 값이 다르면 실제 확대가 모든 역할에 전달되는지 따로 확인한다.

## 표

- 원어/음역·문법·문맥·대표 용례를 작은 화면에서 한 항목씩 세로로 읽는다. 각 셀에는 실제 열 제목을 붙인다. 비교표도 MT/LXX/NT와 해석의 구별이 유지되어야 한다.
- 히브리어의 RTL과 원어 폰트를 유지한다. 열 제목은 한국어 LTR로 읽힌다. 임의로 요약하거나 단어를 생략하지 않는다.
- 문서 전체 overflow가 없다는 검사만으로 통과하지 않는다. 실제 320px와 390px에서 22px 글자로 표의 첫 항목과 마지막 항목, 각 열의 끝까지 읽는다. 셀/표 폭이 화면 안에 있는지, 열 제목이 내용과 맞는지 확인한다.
- 데스크톱과 인쇄에서는 표의 비교 관계를 유지한다. 병합 셀이나 중첩 표는 실제 결과를 개별 검사하고, 해석 관계를 잘못 표시하면 게시하지 않는다.
- 여러 열을 비교하는 표는 실제 열 제목을 명시적인 thead에 둔다. 기존 표의 th가 tbody에 남아 있으면 모바일 라벨만 맞아도 인쇄 머리글 반복이 빠질 수 있다. 내용과 원어를 보존하여 구조를 고친 뒤 모바일·인쇄를 모두 검사한다. 자동 검증도 thead 누락을 거절한다.
- 긴 헬라어·히브리어가 있는 표는 셀 안의 줄바꿈을 허용한다. 셀 자체의 잘림이 없어도 표 전체가 본문 또는 인쇄 영역보다 넓을 수 있으므로, 표와 바깥 영역의 실제 폭을 함께 비교한다. 원어 철자·열·설명을 줄여 맞추지 않는다.

## 읽기 도구

- 장문의 어느 위치에서도 목차·찾기, 요약 보기, 전체 접기/펼치기, 맨 위로를 사용할 수 있어야 한다. 모바일 하단 여백과 safe area를 확보해 마지막 문장이 도구에 가리지 않도록 한다.
- 서술형 배치도 개별 제목을 눌러 접고 펼칠 수 있다. 기본값은 펼침이며, 이 기능 때문에 원고를 일정한 길이로 나누지 않는다.
- 요약에서는 저자가 쓴 summary를 읽고 자세히 보기로 원문에 돌아온다. 전체 접기는 해설에만 적용한다. 성경은 독립 ASIDE로 항상 펼친다.
- 빈 검색창에서는 목차 역할을 하고, 검색에서는 본문과 해설을 찾는다. 접힌 글/요약 중 검색 결과를 선택하면 해당 해설을 펼쳐 자세한 본문으로 이동한다. 검색창 닫기/Escape 뒤 조작 위치로 돌아오는지 확인한다.
- 인쇄에서는 해설 전체를 펼치고 요약·접기 상태와 하단 도구를 인쇄하지 않는다. 인쇄 후 기존 읽기 상태를 복원한다.

## 검토와 기존 게시글

review.json의 mobileTables와 readerControls는 별도 필수 검사다. 실제 측정값·항목·동작을 적고 미실시는 통과시키지 않는다. 테스트 fixture의 성공을 실제 원고의 가독성 심사로 기록하지 않는다.

조립 시 reader_layout.audit가 하단 도구의 중복·누락, 검색창 구성, 항상 펼친 성경, 해설별 본문·작성된 요약, 모바일 표의 열 제목 누락을 별도로 차단한다. 자동 구조 검사 통과는 320/390px·22px에서의 실제 읽기와 기능 검수를 대신하지 않는다. 본문별 구성이나 그림 수를 정하는 검사도 아니다.

모바일 셀의 data-label과 화면에 보이는 열 제목이 서로 같아도 실제 표 머리글과 다르면 거절한다. MT/LXX/NT가 뒤바뀌지 않도록 다행 머리글과 병합 셀의 실제 열 위치까지 대조한다. 표 제목과 첫·마지막 항목의 육안 검수는 계속 별도로 수행한다.

적용 범위를 구별한다. 새 렌더러 또는 공통 기능을 갱신해도 기존 독립 HTML 전체가 자동으로 바뀌지 않는다. 개정한 글은 공개 URL에서 확인하고, 미개정 글은 목록에 남겨 각 글을 검토할 때 함께 적용한다. 공통 읽기 기능 적용과 신학적 내용 검토의 완료 상태를 합쳐 기록하지 않는다.

이미 게시된 reader 1.1 문서는 reader_layout.upgrade로 읽기 기능만 갱신할 수 있다. 함수는 작성된 본문·요약·원어/방향·성경 절·출처 링크·이미지의 동일성을 확인하고 다르면 거절한다. 공개 원본 해시와 새 HTML 해시, 실제 브라우저 검수 근거를 별도의 갱신 기록으로 묶은 뒤 게시한다. 과거 신학 검토가 새 UI 검토를 대신하지 않는다.


기존 해설과 고유 레이아웃이 충분한 글은 `source-reader-plan.json`을 둔 명시적 보존 경로로 개정할 수 있습니다. 지원 프로필은 `sardis-native-v1`, `ezekiel-native-v1`, `luke-9-51-native-v1`, `luke-9-57-native-v1`, `luke-10-native-v1`입니다. 원본 SHA와 선정 본문, 6축 원고 검토의 실제 문장 앵커, 읽은 출처의 범위, 검토 뒤 결정한 기존 SVG 또는 내장 WebP의 해시·목적·육안 확인을 먼저 기록합니다. 원고를 공통 manuscript 형식으로 억지 변환하지 않습니다. 원본 카드 안의 중첩 문법 설명과 세 칸 메모·저장 키·기존 앵커도 보존합니다. 프로필 지원은 실제 원고의 브라우저 심사 통과를 뜻하지 않습니다.

제공된 성경의 각주 표지는 성경 문장과 구별합니다. 누가9:55의 알려진 `2)` 연결은 원래 위치와 연결 대상을 보존하며, `verse-content` 안의 문장만 공식 본문과 대조합니다. 임의 주석이나 추가 문장을 지우고 통과시키는 규칙으로 넓히지 않습니다. 알려지지 않은 표지와 구조는 개별 검토 전 거절합니다.

개별 해설의 보강이 필요하면 `source-content-edits.json`에 해당 카드의 기존 SHA·보강 후 전체 HTML·이유를 적습니다. 제목·작성된 요약·카드 ID는 유지하고, 허용한 본문 안에서 직접 집필합니다. 변경 후 전체 원고의 해시와 실제 문장 앵커를 6축 검토에 결합해야 합니다. 원래 원고만 검토하고 새 문단을 나중에 끼우면 거절합니다. 원어·MT/LXX/NT 비교 등은 본문의 해석 필요에 따라 추가하며 일정한 문단 수나 표 수를 요구하지 않습니다.

이 경로도 성경은 독립 ASIDE여야 하며, 4개 하단 도구·검색·각 셀의 실제 열 제목·모바일 화면과 인쇄를 따로 검사합니다. 단순 정규식으로 중첩 details를 자르지 않습니다. UI 변경은 허용한 정확한 문자열에 한정해 역변환으로 보강 후 원고와 동일한지 검사하며, 최종 출력은 원본·보강·검토·시각 계획·렌더러와 해시로 결합합니다. 보존 검사는 신학 검토를 대신하지 않습니다. 공개 원본 보관은 이 경로의 original.html·published.html과 개인 연구 기록을 제거한 source-layout.json, 사용했다면 source-content-edits.json으로 복구를 확인한 뒤 중복 사본을 정리합니다.

검색이 중첩된 문법 보충을 포함해 찾으면, 결과로 선택한 해설의 내부 설명도 함께 펼칩니다. Escape 닫기와 이전 버튼으로의 초점 복귀는 실제 브라우저에서 따로 확인합니다.

개정 안내문은 실제 변경 범위와 맞아야 합니다. 표 라벨과 읽기 환경만 고친 글을 원어 해설을 보강했다고 표시하지 않습니다. 보존 계획의 `revisionDescription`에 직접 쓴 짧은 설명을 해시로 결합하고 일반 텍스트로 안전하게 표시할 수 있습니다.

이미지 수를 요구하지 않습니다. CSS로 그린 의미 있는 추상 도안도 접근 가능한 설명·캡션과 실제 육안 검토가 있으면 figure 마크업과 원래 style 전체의 SHA를 함께 결합해 보존할 수 있습니다. 별도 도안이 해석에 도움이 되지 않는 글은 빈 시각 목록과 개별 `textOnlyRationale`을 명시할 수 있습니다. 기존 그림의 누락을 이 사유로 숨기면 해시 검증이 거절합니다. 원래 CSS 도안의 구성 보존과 최종 브랜드 색·서체 변경은 구별해 기록합니다.

글자 크기 조작이 실제 표에도 적용되는지 셀의 계산된 font-size로 확인합니다. 표 자체만 가변이어도 셀의 고정 값이나 더 강한 선택자가 남으면 작은 글자가 유지될 수 있습니다. 개별 레이아웃의 기존 저장 키·크기 값과 CSS 변수 이름도 지켜 연결합니다.

최신 누가10처럼 이미 서체와 위계를 다듬은 원고는 기존 5개 폰트 자산의 바이트를 배포 기준과 대조한 뒤 그대로 재사용합니다. 같은 WOFF2를 다시 덧붙여 용량을 늘리지 않습니다. HTML ID가 없는 카드도 검토에는 원래 순서로 결합하며 DOM ID·메모 키를 새로 만들지 않습니다. 원래 JS가 부여하는 앵커를 유지합니다. 표 라벨은 실행 JS에만 의존하지 않고 실제 thead와 행 머리글의 위치를 확인해 HTML에도 내장합니다. 익명 카드의 보강 역시 제목·요약·경계와 원래 SHA를 지켜야 합니다.

일반 reader 원고를 다시 조립할 때도 개정 run ID를 메모의 새 저장 공간으로 쓰지 않습니다. 해시가 결합된 original.html에서 기존 data-storage-issue 또는 data-issue를 읽어 이어받습니다. 실천 문구·순서가 바뀌면 체크 인덱스를 자동으로 넘기지 않고 명시적 매핑 검토 전 거절합니다. 이 경로는 localStorage 값을 읽어 합치거나 지우지 않으므로 기존의 빈 메모와 false도 그대로 남습니다. 알 수 없는 legacy/native 저장 형식을 추측해 이관하지 않습니다. 이미지 최적화처럼 기존 HTML을 직접 보존하는 개정은 원래 data-issue와 JS도 그대로 유지합니다.
