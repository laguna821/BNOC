# BNOC 제작 자동화

Codex가 연구·집필·그림·브라우저 검토를 수행하고, Python 표준 라이브러리 도구가 본문 대조·HTML 조립·중복 방지·Git 게시·배포 확인을 맡습니다. 외부 LLM API 호출이나 API 키는 필요하지 않습니다.

## 한 문장으로 요청

`마태복음 1:1–5를 $bnoc-publish로 만들어 BNOC에 게시해줘.`

`창세기 12:1–3을 $bnoc-publish로 초안만 만들어줘.`

설치할 스킬 원본은 [skill/SKILL.md](skill/SKILL.md)입니다. 스킬 본문과 참조 문서를 설치 폴더에 복사하고, 장치별 `references/local-runtime.json`에는 Python·CLI·config 경로만 기록합니다. 예시 설정은 [config.example.json](config.example.json)입니다. 기본 설정 위치는 사용자 홈의 `Achmage-System/bnoc/config.json`이며 `BNOC_CONFIG`로 변경할 수 있습니다.

## 제작 흐름

주보 확인 → 오전 장년예배 본문 판독 → 로컬 개역개정 조회와 대한성서공회 대조 → 연구 → 상세 원고 → 필요한 시각자료 → SameTone 독립 HTML → 내용·화면 검토 → Git push → Pages 배포 및 검색 목록 확인.

주보의 예배일과 1·2·3부 공통 본문을 사람이 읽듯 실제 이미지로 확인합니다. 오후 예배·새벽기도와 섞지 않습니다. 오전 본문이 다르거나 흐리면 질문합니다. 이미 게시한 주보의 본문이 바뀌면 자동으로 두 번째 글을 올리지 않습니다.

성경 전체 JSON, 주보 원본, 작업 상태, 연구 초안, 검토 기록은 저장소 밖에 둡니다. 게시 명령은 완성 HTML 하나와 작은 발행 manifest 하나만 원격 Git 트리에 추가합니다. 오래된 HTML 파일은 변경하지 않습니다. 같은 날짜·본문·예배는 한 번만 발행합니다.

원어 서체, SameTone 가변 굵기, 로고, 표·제목·본문 위계, 밝은/어두운 테마, 18·20·22px, 검색, 기기 내 메모, HTML 저장, 인쇄 CSS를 공통 제작기가 제공합니다. 원고는 조립할 때 요약하지 않습니다.

## 검토와 재개

`review.json`은 원고·본문·완성 HTML 해시에 연결됩니다. 그림이나 제작기가 변경되어도 다시 조립하고 검토해야 합니다. 출처 확인, 역사·원어, 정론·정행, 평신도 가독성, 그림, 모바일·테마, 검색·메모·다운로드, 인쇄 검토가 모두 기록되어야 게시할 수 있습니다. 검토 여부의 정직성은 실행 에이전트의 책임이며 점수만으로 신학적 정확성을 보장하지 않습니다.

명령 잠금과 작업별 lease가 동시 게시를 막습니다. 중단 후 완료 단계를 재사용하며, 실패한 접근은 바뀐 증거를 기록한 뒤에만 다시 시도합니다. 세 번 실패하면 자동 재시도를 중단합니다. 초안은 명시적으로 promote하기 전에는 게시할 수 없습니다.

## 예약 실행

사용자 장치의 Codex heartbeat가 금·토 06–22시 두 시간마다, 주일 06·08시에 확인합니다(한국 시간). PC와 Codex 실행 환경이 필요합니다. 일정은 장치에 등록되며 이 저장소의 GitHub Actions는 AI 글 생성이 아니라 검증과 Pages 배포를 수행합니다. 새 글이 없는 확인에서는 본문 전체를 읽거나 모델로 해설을 다시 만들지 않습니다.

## 개발 검증

`python -m unittest discover -s automation -p "test_*.py"`

Python 3.11 이상과 Git이 필요합니다. 런타임 Python 패키지 설치는 필요하지 않습니다. 테스트는 합본 절·누락·줄바꿈·중복·오래된 검토·HTML 안전성·실제 로컬 Git 원격 발행을 검증합니다. 연구·문장력 평가는 본문별 검토에 남깁니다.
